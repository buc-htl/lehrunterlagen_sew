Gruppen strukturieren Muster

Runde Klammern fassen Teile eines Musters zusammen. Ein Quantifizierer wirkt dann auf die ganze Gruppe:

(ab)+       "ab" mindestens einmal
(cat|dog)   entweder "cat" oder "dog"
(?:ab)+     "ab" mindestens einmal, ohne Gruppe zu speichern
  • (...) ist eine Capturing Group: Der passende Teil wird gespeichert.
  • (?:...) ist eine Non-Capturing Group: Sie gruppiert, speichert aber nicht.

Capturing Groups auslesen

Die ganze Übereinstimmung hat die Gruppennummer 0; Capturing Groups werden von links nach rechts nummeriert.

Pattern p = Pattern.compile("(\\d{4})-(\\d{2})-(\\d{2})");
Matcher m = p.matcher("Termin: 2026-10-16");

if (m.find()) {
    System.out.println(m.group());    // 2026-10-16
    System.out.println(m.group(1));   // 2026
    System.out.println(m.group(2));   // 10
    System.out.println(m.group(3));   // 16
    System.out.println(m.groupCount()); // 3
}

groupCount() zählt nur Capturing Groups, nicht Gruppe 0 und nicht (?:...).

Gruppen in Ersetzungen verwenden

Die Gruppen eines Treffers lassen sich in Java-Ersetzungstexten wieder einsetzen:

String date = "2026-10-16";
String reordered = date.replaceAll(
    "(\\d{4})-(\\d{2})-(\\d{2})",
    "$3.$2.$1"
);
// Ergebnis: 16.10.2026

$1, $2 usw. verweisen auf nummerierte Gruppen. In Java kann eine benannte Gruppe mit ${name} referenziert werden.

Benannte Gruppen

Eine benannte Gruppe speichert einen Teil des Treffers unter einem verständlichen Namen:

Pattern repeated = Pattern.compile(
    "Wort: (?<word>[A-Za-z]+)!"
);
Matcher m = repeated.matcher("Wort: Hallo!");

if (m.find()) {
    System.out.println(m.group());      // Wort: Hallo!
    System.out.println(m.group("word")); // Hallo
}
  • (?<word>...) markiert den Teil, der als Gruppe word gespeichert wird.
  • m.group() liefert den ganzen Treffer; m.group("word") nur den erfassten Teil.

Benannte Rückverweise

\k<word> bedeutet: Hier muss noch einmal genau der Text stehen, den die benannte Gruppe word zuvor erfasst hat.

Pattern repeated = Pattern.compile(
    "(?<word>[A-Za-z]+)\\s+\\k<word>"
);
Matcher m = repeated.matcher("Hallo Hallo");

if (m.find()) {
    System.out.println(m.group());      // Hallo Hallo
    System.out.println(m.group("word")); // Hallo
}
  • Die Gruppe word erfasst zuerst Hallo.
  • \s+ verlangt mindestens ein Leerraumzeichen dazwischen.
  • \k<word> verlangt denselben Text noch einmal.

Treffer beim Ersetzen wiederverwenden

Auch String.replaceAll() verwendet Gruppenreferenzen im Ersetzungstext. $0 steht für den gesamten Treffer:

String marked = "Raum 12, Stock 3"
    .replaceAll("\\d+", "[$0]");
// Ergebnis: Raum [12], Stock [3]

Lookaround: Kontext prüfen, nicht verbrauchen

Lookaround prüft Zeichen vor oder nach einer Position, ohne diese Zeichen in den Treffer aufzunehmen.

FormBedeutung
(?=...)positiver Lookahead: danach muss ... folgen
(?!...)negativer Lookahead: danach darf ... nicht folgen
(?<=...)positiver Lookbehind: davor muss ... stehen
(?<!...)negativer Lookbehind: davor darf ... nicht stehen

Lookahead: Treffer nach Kontext

Eingabe: host: server

\b\w+\b(?=:)   Treffer: "host" (danach folgt :)
\b\w+\b(?!:)   Treffer: "server" (danach folgt kein :)

Ein Lookahead kann auch Anforderungen prüfen, die an anderer Stelle des Textes erfüllt sein müssen:

^(?=.*\d)[A-Za-z\d]{8,}$

Das Muster verlangt mindestens 8 ASCII-Buchstaben/Ziffern, darunter mindestens eine Ziffer. Der Lookahead prüft die Ziffer, verbraucht aber keine Zeichen und fügt dem Treffer daher keine zusätzliche Länge hinzu.

Lookbehind: Treffer nach Kontext

Eingabe: Preis: $25 und 30

(?<=\$)\d+      Treffer: "25" (davor steht $)
(?<!\$)\b\d+  Treffer: "30" (davor steht kein $)

Die konkrete Unterstützung von Lookbehind hängt von der Java Version ab. Fixe Längen (z.B. nur genau ein Zeichen wie im Beispiel) sind am portabelsten. Prüfe, ob komplexe Formen mit der verwendeten Java-Version funktionieren.

Backtracking: Schritt für Schritt

Backtracking bedeutet: Wenn ein späterer Teil des Musters nicht passt, gibt die Regex-Engine bereits gelesene Zeichen zurück und probiert eine andere Aufteilung.

Muster:  a+ab
Eingabe: aaab
  1. a+ nimmt zunächst möglichst viele a: aaa.
  2. Das nächste Musterzeichen ist a, aber in der Eingabe kommt b: kein Treffer an dieser Stelle.
  3. a+ gibt ein a zurück. Das nächste a im Muster passt nun auf dieses Zeichen.
  4. Das letzte b passt ebenfalls: Treffer ist aaab.

Backtracking begrenzen

Mehrdeutige Wiederholungen können viele Aufteilungen ausprobieren. Oft genügt es, das Muster so zu vereinfachen oder einzugrenzen, dass weniger Aufteilungen möglich sind:


(a+)+$       unnötig verschachtelt, wenn nur a erlaubt ist
a+$          gleiche erlaubte Zeichenfolge, weniger Mehrdeutigkeit

Vermeide, bzw. vereinfache, mehrdeutige, verschachtelte Wiederholungen, um die Performance zu verbessern.

Sichere und performante Regex

  • Eingabelängen begrenzen, besonders bei nicht vertrauenswürdigen Benutzereingaben.
  • Mehrdeutige, verschachtelte Wiederholungen wie (a+)+ vermeiden oder vereinfachen.
  • Muster möglichst eng formulieren: erlaubte Zeichen und Trennzeichen ausdrücklich festlegen.
  • Benutzereingaben, die als wörtlicher Text gesucht werden, mit Pattern.quote() maskieren, statt sie in das Regex-Muster einzubauen.
  • Ein wiederholt verwendetes Muster einmal mit Pattern.compile() erstellen und wiederverwenden, statt es bei jeder Suche neu zu kompilieren.

Java-RegEx-Muster für Benutzereingaben nicht unbeschränkt ausführen: Java Pattern bietet keine eingebaute Laufzeitbegrenzung.

Unicode: Code Units, Code Points, Grapheme

  • Code Unit: einzelne 16-Bit-Einheit der UTF-16-Kodierung.
  • Code Point: ein nummerierter Unicode-Zeichenwert.
  • Graphem: eine für Menschen als einzelnes Zeichen wahrgenommene Einheit; sie kann aus mehreren Code Points bestehen.
BeispielCode UnitsCode PointsGraphem
A111
😀211
e + U+0301 (erscheint als é)221
é (U+00E9)111

Unicode in Java und Regex


String text = "é😀e\u0301"; //é😀é
Matcher matcher = Pattern.compile(".").matcher(text);
while (matcher.find()) {
    System.out.printf("start=%d, end=%d, Treffer=\"%s\"%n",
        matcher.start(), matcher.end(), matcher.group());
}
// Ausgabe:
// start=0, end=1, Treffer="é"
// start=1, end=3, Treffer="😀"
// start=3, end=4, Treffer="e"
// start=4, end=5, Treffer="́"
  • Der Punkt . trifft auf jeden einzelnen Code Point zu, nicht auf Grapheme.
  • Das zusammengesetzte é (U+00E9) ist ein Code Point. Das Emoji ist ebenfalls ein Code Point, belegt in UTF-16 aber zwei Code Units; darum reichen seine Indizes von 1 bis 3.
  • e und der kombinierende Akzent bilden die zerlegte Schreibweise von é: zwei Code Points, die von . getrennt gefunden werden.
  • Beide Schreibweisen sehen gleich aus. Java normalisiert Strings nicht automatisch; Unicode-Normalisierung wie NFC kann die zerlegte Schreibweise in die zusammengesetzte überführen (siehe java.text.Normalizer-API).

Grapheme mit \X finden


String text = "é😀e\u0301"; //é😀é
Matcher matcher = Pattern.compile("\\X").matcher(text);
while (matcher.find()) {
    System.out.printf("start=%d, end=%d, Treffer=\"%s\"%n",
        matcher.start(), matcher.end(), matcher.group());
}
// Ausgabe:
// start=0, end=1, Treffer="é"
// start=1, end=3, Treffer="😀"
// start=3, end=5, Treffer="é"
  • In Java 9+ findet \X Grapheme: Das zusammengesetzte é wird als ein Treffer gefunden, ebenso das Emoji.
  • e und der kombinierende Akzent werden gemeinsam als ein Graphem gefunden, obwohl sie aus zwei Code Points bestehen.
  • start() und end() geben weiterhin UTF-16-Indizes an: Das Emoji belegt zwei Code Units, e samt Akzent ebenfalls.

Unicode-Kategorien

Java-Regex kann Zeichen anhand ihrer Unicode-General-Category auswählen:

RegexBedeutungBeispiele
\p{L}alle BuchstabenA, ä, ǅ
\p{Ll}Kleinbuchstabena, ä
\p{Lu}GroßbuchstabenA, Ä
\p{Lt}Unicode-Titelbuchstabenǅ
\p{Z}Trennzeichen, z. B. LeerzeichenLeerzeichen, geschütztes Leerzeichen
\p{N}Zahlen: Dezimalziffern, Buchstabenzahlen und sonstige Zahlen7, Ⅷ, ½

Übersicht aller Unicode-General-Categories: Unicode Character Database – General_Category Values.

Unicode-Kategorien in Java verwenden

"ä".matches("\\p{L}"); // true: Buchstabe
"7".matches("\\p{N}"); // true: Zahl

Die Beispiele prüfen, ob der jeweilige Text aus einem Zeichen der angegebenen Unicode-Kategorie besteht.

\p{L} vs \w

Pattern letters = Pattern.compile("\\p{L}+");
Pattern wordChars = Pattern.compile("\\w+", Pattern.UNICODE_CHARACTER_CLASS);
  • \p{L} sagt präzise: Es sind Unicode-Buchstaben gemeint. Das Muster funktioniert ohne zusätzliches Flag.
  • \w mit UNICODE_CHARACTER_CLASS ist breiter: Es umfasst auch Ziffern, kombinierende Zeichen und Verbindungszeichen wie den Unterstrich.
  • Wenn eine Anforderung wirklich „Buchstaben“ lautet, ist \p{L} dadurch klarer und lässt nicht versehentlich Ziffern oder _ zu.
  • Kombinierende Zeichen sind Zusatzzeichen, etwa ein Akzent, der zu einem Buchstaben gehört. In e\u0301 (e + Akzent) ist der Akzent ein eigenes Zeichen, das zusammen mit e als é erscheint.
  • Bei dieser zerlegten Schreibweise passt \p{L} nur auf das e, nicht auf den Akzent; \w mit UNICODE_CHARACTER_CLASS berücksichtigt auch kombinierende Zeichen.

Regex-Flavors unterscheiden sich

Regex-Engines in verschiedenen Programmiersprachen/Versionen können sich unterscheiden. Ein Muster ist nicht automatisch übertragbar!

BereichWas variieren kann
KurzklassenBedeutung von \w, \d, \b und Unicode-Optionen
LookbehindErlaubte Längen und Konstrukte unterscheiden sich nach Engine/Version
Benannte GruppenSchreibweise für Definition, Rückverweis und Ersetzung kann abweichen
ErsetzungSyntax für Gruppenreferenzen im Ersetzungstext ist engineabhängig
OptionenStandardwerte für Groß-/Kleinschreibung und Zeilenumbrüche sind nicht überall gleich

Immer mit der Regex-Engine und Version des Zielsystems testen.

Was ist ein Tokenizer?

Ein Tokenizer zerlegt einen Text von links nach rechts in bedeutungstragende Einheiten, sogenannte Tokens.

total = 12 + count
Bezeichner  Operator  Zahl  Operator  Bezeichner
   total       =       12      +       count
  • Jedes Token hat einen Typ, zum Beispiel Bezeichner, Zahl oder Operator.
  • Leerraum kann als Token erfasst oder beim Lesen übersprungen werden.
  • Ein Tokenizer erkennt die Einheiten; welche Kombinationen davon gültig sind, prüft anschließend ein Parser.

Tokenizer mit Regex definieren

Ein Tokenizer erkennt mehrere Tokenarten, zum Beispiel Leerraum, Zahlen, Bezeichner und Operatoren.

Pattern token = Pattern.compile(
    "(?<ws>\\s+)"                         // Leerraum
  + "|(?<number>\\d+(?:\\.\\d+)?)"         // Zahl
  + "|(?<identifier>\\p{L}[\\p{L}\\p{N}_]*)" // Bezeichner
  + "|(?<operator>[+=*/()-])"             // Operator
);
String input = "total = 12 + count";

Der Tokenizer soll den Text vollständig vom Anfang bis zum Ende in Tokens zerlegen – ohne Zeichen zu übergehen.

Tokenizer: Unbekannte Zeichen erkennen

Unbekannte Zeichen im Eingabestring sollen erkannt und als Fehler behandelt werden. Der Positionsvergleich verhindert, dass find() ungültige Zeichen still überspringt.


//Fortsetzung Code der vorigen Folie:
Matcher m = token.matcher(input);
int position = 0;
while (m.find()) {
    if (m.start() != position) {
        throw new IllegalArgumentException("Unbekanntes Zeichen bei " + position);
    }
    if (m.start("ws") < 0) { // Es liegt kein Leerraum-Treffer vor
        String type = m.start("number") >= 0 ? "number"
            : m.start("identifier") >= 0 ? "identifier" : "operator";
        System.out.println(type + ": " + m.group());
    }
    position = m.end();
}
if (position != input.length()) {
    throw new IllegalArgumentException("Unbekanntes Zeichen bei " + position);
}

Was macht der Parser?

Nach dem Tokenizer könnte ein Parser prüfen, ob die Token in einer erlaubten Reihenfolge stehen und eine gültige Struktur bilden.

total = 12 + count
Bezeichner = Zahl + Bezeichner    gültiger Ausdruck

+ = total                         ungültige Reihenfolge
total = 12 +                      unvollständiger Ausdruck

Die bisherige Tokenizer-Folie erkennt Token und unbekannte Zeichen, prüft aber noch keine solche Grammatik.
