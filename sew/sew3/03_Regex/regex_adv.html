Gruppen strukturieren Muster

Runde Klammern fassen Teile eines Musters zusammen. Ein Quantifizierer wirkt dann auf die ganze Gruppe:

(ab)+       "ab" mindestens einmal
(cat|dog)   entweder "cat" oder "dog"
(?:ab)+     "ab" mindestens einmal, ohne Gruppe zu speichern
  • (...) ist eine Capturing Group: Der passende Teil wird gespeichert.
  • (?:...) ist eine Non-Capturing Group: Sie gruppiert, speichert aber nicht.

Capturing Groups auslesen

Die ganze Übereinstimmung hat die Gruppennummer 0; Capturing Groups werden von links nach rechts nummeriert.

Pattern p = Pattern.compile("(\\d{4})-(\\d{2})-(\\d{2})");
Matcher m = p.matcher("Termin: 2026-10-16");

if (m.find()) {
    System.out.println(m.group());    // 2026-10-16
    System.out.println(m.group(1));   // 2026
    System.out.println(m.group(2));   // 10
    System.out.println(m.group(3));   // 16
    System.out.println(m.groupCount()); // 3
}

groupCount() zählt nur Capturing Groups, nicht Gruppe 0 und nicht (?:...).

Gruppen in Ersetzungen verwenden

Die Gruppen eines Treffers lassen sich in Java-Ersetzungstexten wieder einsetzen:

String date = "2026-10-16";
String reordered = date.replaceAll(
    "(\\d{4})-(\\d{2})-(\\d{2})",
    "$3.$2.$1"
);
// Ergebnis: 16.10.2026

$1, $2 usw. verweisen auf nummerierte Gruppen. In Java kann eine benannte Gruppe mit ${name} referenziert werden.

Benannte Gruppen

Eine benannte Gruppe speichert einen Teil des Treffers unter einem verständlichen Namen:

Pattern repeated = Pattern.compile(
    "Wort: (?<word>[A-Za-z]+)!"
);
Matcher m = repeated.matcher("Wort: Hallo!");

if (m.find()) {
    System.out.println(m.group());      // Wort: Hallo!
    System.out.println(m.group("word")); // Hallo
}
  • (?<word>...) markiert den Teil, der als Gruppe word gespeichert wird.
  • m.group() liefert den ganzen Treffer; m.group("word") nur den erfassten Teil.

Benannte Rückverweise

\k<word> bedeutet: Hier muss noch einmal genau der Text stehen, den die benannte Gruppe word zuvor erfasst hat.

Pattern repeated = Pattern.compile(
    "(?<word>[A-Za-z]+)\\s+\\k<word>"
);
Matcher m = repeated.matcher("Hallo Hallo");

if (m.find()) {
    System.out.println(m.group());      // Hallo Hallo
    System.out.println(m.group("word")); // Hallo
}
  • Die Gruppe word erfasst zuerst Hallo.
  • \s+ verlangt mindestens ein Leerraumzeichen dazwischen.
  • \k<word> verlangt denselben Text noch einmal.

Lookaround: Kontext prüfen, nicht verbrauchen

Lookaround prüft Zeichen vor oder nach einer Position, ohne diese Zeichen in den Treffer aufzunehmen.

FormBedeutung
(?=...)positiver Lookahead: danach muss ... folgen
(?!...)negativer Lookahead: danach darf ... nicht folgen
(?<=...)positiver Lookbehind: davor muss ... stehen
(?<!...)negativer Lookbehind: davor darf ... nicht stehen

Lookahead: Treffer nach Kontext

Eingabe: host: server

\b\w+(?=:)     findet "host"
\b\w+(?!:)     findet Wörter, auf die kein Doppelpunkt folgt

Der Doppelpunkt wird geprüft, gehört aber nicht zum Treffer. Ein Lookahead kann auch Anforderungen prüfen, die an anderer Stelle des Textes erfüllt sein müssen:

^(?=.*\d)[A-Za-z\d]{8,}$

Das Muster verlangt mindestens 8 ASCII-Buchstaben/Ziffern und irgendwo mindestens eine Ziffer. Für echte Passwortregeln zusätzlich passende Unicode- und Sicherheitsanforderungen beachten.

Lookbehind: Treffer nach Kontext

Eingabe: Preis: $25 und 30

(?<=\$)\d+    findet "25" direkt nach $
(?<!\$)\b\d+    findet Zahlen, vor denen kein $ steht

Lookbehind nimmt den geprüften Kontext nicht in den Treffer auf. Java unterstützt nicht jede beliebige Lookbehind-Form; feste Längen sind am portabelsten. Prüfe komplexe Formen mit der verwendeten Java-Version.

Backtracking: Wie sucht die Engine?

Eine Backtracking-Engine probiert Wiederholungen und Alternativen aus. Reicht ein späterer Teil des Musters nicht, geht sie zurück und versucht eine andere Aufteilung.

Muster:   (a+)+$
Eingabe:  aaaaa!
  • Die vielen a können auf zahlreiche Weisen auf die inneren a+-Gruppen verteilt werden.
  • Das abschließende ! verhindert den Treffer; die Engine kann viele Aufteilungen erfolglos prüfen.
  • Mit längeren, speziell geformten Eingaben kann die Laufzeit stark anwachsen.

Backtracking begrenzen

Wenn nur eine Folge von a erlaubt ist, genügt das einfachere Muster:

(a+)+$   unnötig verschachtelte Wiederholung
a+$      gleiche gewünschte Zeichenfolge, weniger Mehrdeutigkeit

Possessive Quantifizierer und atomare Gruppen geben bereits konsumierten Text nicht zum erneuten Ausprobieren frei:

        \d+\d       kann Ziffern zurückgeben, um die letzte \d zu erfüllen
        \d++\d      gibt keine Ziffer zurück und scheitert bei "123"
        (?>\d+)\d   atomare Gruppe: ebenfalls kein Zurückgeben

Possessiv/atomar nur einsetzen, wenn das Zurückgeben fachlich nicht gebraucht wird; sonst ändert sich das Ergebnis.

Regex-Performance sicher messen

  • Bei Benutzereingaben: Länge begrenzen und Eingaben als nicht vertrauenswürdig behandeln.
  • Mehrdeutige, verschachtelte Wiederholungen wie (a+)+ vermeiden oder vereinfachen.
  • Erfolg und Fehlschlag mit kurzen, langen und speziell ungünstigen Testdaten prüfen.
  • Vergleiche mit JVM-Warm-up und vielen Wiederholungen durchführen; für Java ist JMH geeigneter als eine einzelne Stoppuhrmessung.

Eine einzelne Zeitmessung ist kein belastbarer Benchmark. Gefährliche Muster nicht mit unbeschränkten Eingaben in Produktion testen.

Unicode: Code Units, Code Points, Grapheme

  • UTF-16-Code-Unit: Java-char und String-Indizes zählen 16-Bit-Einheiten.
  • Code Point: Unicode-Zeichenwert; ein Zeichen außerhalb der BMP belegt in Java zwei Code Units.
  • Graphem: vom Menschen wahrgenommenes Zeichen; kann aus mehreren Code Points bestehen, etwa Buchstabe plus kombinierendes Zeichen oder Emoji-Sequenz.

Matcher.start() und end() liefern Java-String-Indizes (UTF-16-Code-Units), nicht Graphempositionen.

Unicode-Eigenschaften in Java

Pattern letters = Pattern.compile("\\p{L}+");
Pattern greek = Pattern.compile("\\p{IsGreek}+");
  • \p{L}: Unicode-Kategorie „Letter“ (Buchstabe), unabhängig von einem festen Alphabet.
  • \p{IsGreek}: Zeichen aus dem griechischen Skript.
  • \d, \w und \s sind nicht in jeder Regex-Engine gleich definiert.
  • In Java erweitert Pattern.UNICODE_CHARACTER_CLASS die vordefinierten Klassen wie \w und \d in Richtung Unicode.

Wenn Unicode-Buchstaben gefordert sind, ist \p{L} meist klarer als die Annahme, \w bedeute überall dasselbe.

Regex-Flavors unterscheiden sich

Ein Regex-Muster ist nicht automatisch zwischen Programmen übertragbar:

BereichWas variieren kann
KurzklassenBedeutung von \w, \d, \b und Unicode-Optionen
LookbehindErlaubte Längen und Konstrukte unterscheiden sich nach Engine/Version
Benannte GruppenSchreibweise für Definition, Rückverweis und Ersetzung kann abweichen
Java und PythonGruppe: (?<name>...) vs. (?P<name>...); Rückverweis: \k<name> vs. (?P=name)
ErsetzungJava: ${name}; Python: \g<name>
OptionenStandardwerte für Groß-/Kleinschreibung und Zeilenumbrüche sind nicht überall gleich

Immer Engine und Version des Zielsystems testen, zum Beispiel Java Pattern statt nur „Regex“ anzugeben.

Optionen: Groß-/Kleinschreibung und Zeilen

Pattern p = Pattern.compile(
    "^java$",
    Pattern.CASE_INSENSITIVE | Pattern.UNICODE_CASE | Pattern.MULTILINE
);
  • CASE_INSENSITIVE: ignoriert Groß-/Kleinschreibung; für Unicode-Fälle zusätzlich UNICODE_CASE.
  • MULTILINE: ^ und $ beziehen sich auf Zeilenanfang und -ende.
  • DOTALL: . passt auch auf Zeilenumbruchzeichen.

Inline-Optionen: (?i), (?m), (?s). Optionen gelten ab ihrer Stelle im Muster; mit (?i:...) lässt sich ein Teilbereich einschließen.

Pattern acrossLines = Pattern.compile("start.*end", Pattern.DOTALL);
Pattern lineOnly = Pattern.compile("^java$", Pattern.MULTILINE);

Höhere Java-APIs für Treffer

import java.util.List;
import java.util.regex.MatchResult;
import java.util.regex.Pattern;

Pattern numbers = Pattern.compile("\\d+");

List<String> found = numbers.matcher("Raum 12, Stock 3")
    .results()
    .map(MatchResult::group)
    .toList();
  • Matcher.results(): Stream der Treffer, die find() liefern würde.
List<String> parts = Pattern.compile("\\s+")
    .splitAsStream("rot blau gruen")
    .toList();

boolean hasNumber = Pattern.compile("\\d+")
    .asPredicate()
    .test("Raum 12"); // true: asPredicate verwendet find

splitAsStream() liefert einen Stream, der erst beim Verarbeiten konsumiert wird.

Beispiele mit Stream.toList() benötigen Java 16 oder neuer.

Funktionale Ersetzung

In Java kann die Ersetzung für jeden Treffer anhand des Match-Ergebnisses berechnet werden:

Pattern numbers = Pattern.compile("\\d+");
String marked = numbers.matcher("Raum 12, Stock 3")
    .replaceAll(match -> "[" + match.group() + "]");
// Ergebnis: Raum [12], Stock [3]

Das ist nützlich, wenn die Ersetzung vom gefundenen Text oder seinen Gruppen abhängt, statt für alle Treffer gleich zu sein.

Tokenizer: Text in Token zerlegen

Ein Tokenizer erkennt mehrere Tokenarten, zum Beispiel Leerraum, Zahlen, Bezeichner und Operatoren.

Pattern token = Pattern.compile(
    "(?<ws>\\s+)"
  + "|(?<number>\\d+(?:\\.\\d+)?)"
  + "|(?<identifier>\\p{L}[\\p{L}\\p{N}_]*)"
  + "|(?<operator>[+=*/()-])"
);
String input = "total = 12 + count";

Die benannten Gruppen klassifizieren Treffer. Der nächste Schritt ist, mit Matcher lückenlos von links nach rechts zu lesen.

Tokenizer: Lücken erkennen

Fortsetzung des Beispiels mit token und input von der vorigen Folie:

Matcher m = token.matcher(input);
int position = 0;
while (m.find()) {
    if (m.start() != position) {
        throw new IllegalArgumentException("Unbekanntes Zeichen bei " + position);
    }
    if (m.start("ws") < 0) {
        String type = m.start("number") >= 0 ? "number"
            : m.start("identifier") >= 0 ? "identifier" : "operator";
        System.out.println(type + ": " + m.group());
    }
    position = m.end();
}
if (position != input.length()) {
    throw new IllegalArgumentException("Unbekanntes Zeichen bei " + position);
}

Der Positionsvergleich verhindert, dass find() ungültige Zeichen still überspringt. Für eine echte Programmiersprache wären zusätzlich Kommentare, Zeichenketten und Grammatikregeln nötig.
