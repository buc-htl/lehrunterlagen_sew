Was sind reguläre Ausdrücke?

Ein regulärer Ausdruck (English: regular expression) ist ein Textmuster, das beschreibt, welche Zeichenfolgen in einem Text gesucht oder akzeptiert werden.

Der englische Ausdruck wird meist zu Regex abgekürzt (Plural: Regexes). Wir verwenden im Folgenden den Begriff Regex.

Wofür sind Regex nützlich?

  • Suchen: Wo kommt eine Zeichenfolge im Text vor?
  • Prüfen: Hat ein String das richtige Format? (z.B. Datum, E-Mail-Adresse)
  • Extrahieren: Textstellen aus einem größeren Text herausnehmen
  • Ersetzen: Textstellen im Text suchen und ersetzen

Regex haben Grenzen

  • Regex eignen sich gut für klar beschreibbare Textmuster.
  • Beliebig verschachtelte Strukturen, z. B. Klammern beliebiger Tiefe, lassen sich damit nicht zuverlässig parsen.
  • Für komplexere Aufgaben kombiniert man Regex mit Logik im Code.
  • Beispiel: Man überprüft mit Regex das grundlegende Format eines Datum, aber nicht, ob es ein gültiges Datum ist.

Muster, Eingabe, Treffer

Muster: cat
Eingabe: The cat sleeps.
Treffer:     cat
  • Das Muster (i.e. die Regex) beschreibt den gesuchten Text.
  • Die Eingabe ist der Text, in dem gesucht oder geprüft wird.
  • Ein Treffer ist ein Teil der Eingabe, der zum Muster passt.

Literale und Sonderzeichen

Die meisten Buchstaben und Ziffern stehen für sich selbst:

Regex: cat     passt auf "cat"
Regex: 2026    passt auf "2026"

Einige Zeichen haben eine besondere Bedeutung, zum Beispiel:

.  ^  $  *  +  ?  [ ]  { }  ( )  |  \

Zeichenklassen

Eckige Klammern erlauben ein Zeichen aus einer Auswahl:

Beispiele: 
[aeiou]    ein Kleinbuchstabe aus dieser Auswahl
[A-Z]      ein Großbuchstabe von A bis Z (Bereich)
[^0-9]     ein Zeichen, das keine Ziffer ist (^ leitet Negation ein)

[aeiou] matcht die Strings "a", "e", "i", "o", "u"
[a-z] matcht "a","b",....."z"  
[^0-9] match "A", "a", "!", ...

[aeiou] z.B. matcht genau einen Vokal, nicht das z.B. ganze Wort „apfel“.

Abkürzungen für Zeichen


\d    eine Ziffer
\w    ein Wortzeichen
\s    ein Whitespace-Zeichen
\D    keine Ziffer
\W    kein Wortzeichen
\S    kein Whitespace-Zeichen

Beispiele:
\d\w    matcht eine Ziffer gefolgt von einem Wortzeichen (z.B. "3a")
\d\d   matcht zwei Ziffern (z.B. "42")

Die genaue Bedeutung (z.B. was ist ein Wortzeichen) kann von Regex-Engine und Optionen abhängen.

Der Punkt als Platzhalter

Der Punkt steht für ein beliebiges Zeichen außer einem Zeilenumbruch.


c.t     matcht z.B. cat, cut und c7t
.b..    matcht z.B. abcd, 1b23, .b..

Ein Sonderzeichen suchen

  • Ein Backslash (\) hebt die Sonderbedeutung eines Zeichens auf.
  • Beispiel:
    • Ein Punkt (.) hat eine besondere Bedeutung(siehe diese Folie).
    • Um einen Punkt selbst zu suchen, muss man ihn mit einem Backslash escapen. 
      
\.     matcht einen Punkt (".")
.      matcht ein beliebiges Zeichen
a\.2   matcht a.2, aber nicht z.B. aX2

Java: Warum zwei Backslashes? (1/2)

Ein Regex-Muster wird in Java als String geschrieben. Dadurch wird der Text zweimal interpretiert:

  1. Java-Compiler: verarbeitet Escape-Sequenzen (z.B. \n, \t, \\) im String-Literal: Zwei Backslashes \\ im Java-Quelltext ergeben einen Backslash im String. Diesen einzelnen Backslash erhält anschließend die Regex-Engine.
  2. Regex-Engine: erhält den fertigen String und liest ihn als Muster.
String regex = "\\.";  // Java-Quelltext
// String enthält: \.   -> Regex: ein Punkt

Das Literal "\\" im String ergibt einen Backslash im Regex.

Java: Warum zwei Backslashes? (2/2)

String a = "\.";   // Compilerfehler: ungültige Escape-Sequenz
String b = "\\.";  // String: \.  -> Regex: wörtlicher Punkt
String c = "\\d";  // String: \d  -> Regex: eine Ziffer
  • Der Compiler kennt \. nicht als Escape-Sequenz und meldet einen Fehler.
  • Bei Muster \d gilt dasselbe: Im Quelltext schreibst du "\\d".
  • Einen echten Backslash im Text suchen: Regex \\ → im Java-Quelltext "\\\\".
  • Merkregel: Soll ein Backslash als Regex-Syntax bei der Regex-Engine ankommen, musst du ihn im Java-String verdoppeln.

Wie oft darf etwas vorkommen?

Die Quantifizierer *, +, ?, {n}, {n,m} geben an, wie oft etwas vorkommen darf. 


a*       null oder mehr a (nichts oder beliebig viele)
a+       ein oder mehr a (beliebig viele, min. 1)
a?       null oder ein a (optional)
a{3}     genau drei a
a{2,4}   zwei bis vier a

Quantifizierer beziehen sich auf das vorangehende Zeichen oder Element.

Greedy und lazy

  • Greedy (gierig, Standard): Der Quantifizierer nimmt so viel Text wie möglich, solange das gesamte Muster noch passt.
  • Lazy (genügsam): Ein ? hinter dem Quantifizierer, z. B. *?, +?, ?? oder {n,m}?, nimmt so wenig Text wie möglich.
greedy:  .*     .+     .?     .{2,5}
lazy:    .*?    .+?    .??    .{2,5}?

Beide Varianten finden einen Treffer, der zum Muster passt, aber evtl. unterschiedlich lang ist.

Greedy und lazy: Beispiel

Eingabe: <b>eins</b> und <b>zwei</b>
MusterArtTreffer
<b>.*</b>greedy1 Treffer:
<b>eins</b> und <b>zwei</b>
<b>.*?</b>lazy2 Treffer:
<b>eins</b>
<b>zwei</b>

Greedy läuft mit .* bis zum Textende und geht nur so weit zurück, bis </b> passt (das letzte). Lazy stoppt beim ersten </b>.

Lazy ist nicht automatisch „richtig“. (HTML verarbeitet man in der Praxis mit einem Parser.)

Wo im Text soll der Treffer liegen?

^      Anfang der Eingabe
$      Ende der Eingabe
\b     Grenze zwischen Wort- und Nicht-Wortzeichen

Beispieltext: "AB123x und AB123" — gesucht wird mit find() nach zwei Großbuchstaben und drei Ziffern:

Muster                 Treffer
[A-Z]{2}\d{3}          AB123 (am Anfang), AB123 (am Ende)
^[A-Z]{2}\d{3}         AB123 (nur am Anfang)
[A-Z]{2}\d{3}$         AB123 (nur am Ende)
\b[A-Z]{2}\d{3}\b      AB123 (nur als ganzes Wort)
^[A-Z]{2}\d{3}$        kein Treffer (die ganze Eingabe passt nicht)

Ohne Anker darf der Treffer an beliebiger Stelle liegen. ^ und $ beschränken seine Position; mit beiden muss die ganze Eingabe dem Muster entsprechen.

Alternativen mit |

Der senkrechte Strich bedeutet „oder“:

cat|dog

Das Muster passt auf cat oder dog.

Achte darauf, ob die Alternative den ganzen Text oder nur einen Teil davon beschreiben soll.

(rot|blau)es Auto
rotes Auto   Treffer
blaues Auto  Treffer
rotes Haus   kein Treffer

Die Klammern begrenzen die Alternative auf rot oder blau; danach muss in beiden Fällen es Auto folgen.

Muster lesen - ein Beispiel

^[A-Z]{2}\d{3}.?
  1. ^: am Anfang
  2. [A-Z]{2}: genau zwei Großbuchstaben
  3. \d{3}: gefolgt von genau drei Ziffern
  4. .?: optional ein beliebiges Zeichen

Beispiel bei Prüfung des gesamten Textes (keine Teilstrings):

AB123    Match
AB123x   Match
AB123xy  kein Match (mehr als ein optionales Zeichen)
Ab123    kein Match (b statt B)
AB12     kein Match (zu wenige Ziffern)
aAB123x  kein Match ("falsches" Zeichen am Anfang)

Muster entwerfen

Anforderung: Eine Kennung besteht aus zwei Großbuchstaben und drei Ziffern.

  1. Welche Zeichen sind erlaubt?
  2. Wie viele davon und in welcher Reihenfolge?
  3. Soll nur ein Teilstring oder die ganze Eingabe passen?
  4. Lege Beispiele fest und überprüfe dein Muster damit.

Baue das Muster Schritt für Schritt und teste jede Entscheidung. Ein Regex-Tester oder Debugger kann Treffer und Fehlschläge sichtbar machen.

Muster: [A-Z]{2}[0-9]{3}
AB123     zwei Großbuchstaben, dann drei Ziffern
xAB123y   enthält dieses Muster als Teilstring
  • Validieren: Passt die ganze Eingabe?
  • Suchen: Kommt das Muster irgendwo vor?
  • Präfix prüfen: Beginnt der Text mit einem Treffer?

Java: Pattern und Matcher erstellen

  1. Pattern.compile() erstellt ein verwendbares Regex-Muster.
  2. pattern.matcher(text) verbindet das Muster mit einem Eingabetext.
import java.util.regex.Matcher;
import java.util.regex.Pattern;

Pattern pattern = Pattern.compile("\\d+");
String text = "12 und 3";
Matcher matcher = pattern.matcher(text);

Hier sucht das Muster \d+ nach einer oder mehreren Ziffern.

Java: Match oder Suche?

Mit demselben Muster und Text beantworten diese Methoden unterschiedliche Fragen:

AufrufWas wird geprüft?Ergebnis Beispiel
matcher.matches()Passt der ganze Text?false
matcher.find()Gibt es Treffer im Text?true
matcher.lookingAt()Passt es ab Textanfang?true

Jede Methode liefert einen boolean zurück.

Java: Treffer mit find() auslesen

matcher.find() sucht ab der aktuellen Position den nächsten Treffer. Wiederholte Aufrufe finden weitere Treffer:

Pattern pattern = Pattern.compile("\\d+");
Matcher matcher = pattern.matcher("Raum 12, Stock 3");

while (matcher.find()) {
    System.out.println(matcher.group()
        + " bei " + matcher.start() + "–" + matcher.end());
}
  • matcher.group(): den gefundenen Text
  • matcher.start(): Index des ersten Trefferzeichens
  • matcher.end(): Index direkt nach dem Treffer (Ende exklusiv)

Die Ausgabe enthält die Treffer 12 bei 5–7 und 3 bei 15–16.

Java: Mehrere Zeilen mit MULTILINE

Das Flag Pattern.MULTILINE verändert die Anker ^ und $:

String text = "java\nregex";

Pattern normal = Pattern.compile("^java$");
Pattern perLine = Pattern.compile("^java$", Pattern.MULTILINE);

normal.matcher(text).find();    // false: "java" ist nicht die ganze Eingabe
perLine.matcher(text).find();   // true: "java" ist eine eigene Zeile
  • Ohne MULTILINE beziehen sich ^ und $ auf Anfang und Ende der gesamten Eingabe.
  • Mit MULTILINE beziehen sich ^ und $ auf Anfang und Ende jeder Zeile.

Sonderfall: Ohne MULTILINE passt $ in Java auch direkt vor einem Zeilenumbruch, der das letzte Zeichen der Eingabe ist.

Pattern p = Pattern.compile("^java$");

p.matcher("java").find();     // true
p.matcher("java\n").find();   // true: $ passt vor dem abschließenden \n
p.matcher("java\nx").find();  // false: \n ist nicht das letzte Zeichen

Soll wirklich nur das Eingabeende passen, verwendet man \z statt $.

Java: Zeilenumbrüche mit DOTALL

Das Flag Pattern.DOTALL verändert den Punkt .:

String text = "java\nregex";

Pattern normal = Pattern.compile("java.regex");
Pattern dotAll = Pattern.compile("java.regex", Pattern.DOTALL);

normal.matcher(text).find();   // false: . passt nicht auf \n
dotAll.matcher(text).find();   // true: . passt auch auf \n
  • Ohne DOTALL passt . auf kein Zeilenumbruchzeichen.
  • Mit DOTALL passt . auf jedes Zeichen, auch auf Zeilenumbrüche.

MULTILINE und DOTALL ändern unterschiedliche Dinge und lassen sich kombinieren: Pattern.MULTILINE | Pattern.DOTALL.

Java: Regex-Methoden von String

Die Klasse String bietet mehrere Methoden an, die Regex verwenden:

String text = "Raum 12, Stock 3";

text.matches(".*\\d+.*");       // true: ganzer Text passt auf dieses Muster
text.split("\\s+");             // ["Raum", "12,", "Stock", "3"]
text.replaceAll("\\s+", "_");   // "Raum_12,_Stock_3"
text.replaceFirst("\\d+", "#"); // "Raum #, Stock 3"

matches() prüft immer den ganzen String. Für eine Suche nach einem Teilstück verwendet man Matcher.find().

Treffer ersetzen

Allgemein: Ein Ersetzungstext ersetzt die Textstellen, die zum Muster passen.

"a   b \t c".replaceAll("\\s+", " ");        // "a b c"  (Leerraum normalisieren)
"Tel: 0664 123456".replaceAll("\\d", "#");   // "Tel: #### ######"  (Ziffern maskieren)
"Raum 12, Stock 3".replaceAll("\\d+", "X");  // "Raum X, Stock X"
"Raum 12, Stock 3".replaceFirst("\\d+", "X");// "Raum X, Stock 3"  (nur der erste Treffer)
"a.b.c".replaceAll("\\.", "");               // "abc"  (Punkte entfernen)

Im Ersetzungstext haben $ und \ eine Sonderbedeutung (z.B. $1 für Gruppen). Soll ein dynamischer Ersetzungstext wörtlich eingesetzt werden, dann verwende Matcher.quoteReplacement():

String price = "Preis: 5 EUR";
price.replaceAll("\\d+", "$5");   // IndexOutOfBoundsException: $5 meint Gruppe 5
price.replaceAll("\\d+", Matcher.quoteReplacement("$5"));   // "Preis: $5 EUR"

Ungültige Regex erkennen

Ein syntaktisch ungültiges Muster kann beim Kompilieren eine PatternSyntaxException auslösen.

try {
    Pattern.compile("[");
} catch (PatternSyntaxException e) {
    System.out.println(e.getDescription());
}

Bei fest eingebauten Mustern sollte der Fehler beim Entwickeln gefunden werden. Behandle Ausnahmen gezielt.
