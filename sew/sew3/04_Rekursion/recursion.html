Rekursion

Ein Problem lösen, indem man kleinere Versionen desselben Problems löst

Grundlagen mit Java-Beispielen

Was du nachher kannst

  • Rekursion erklären und von Iteration unterscheiden
  • Abbruchbedingung, Basisfall und rekursiven Fall in einer Methode finden
  • entscheiden, ob ein Problem eine passende rekursive Struktur hat
  • eine rekursive Lösung Schritt für Schritt entwickeln und verfolgen
  • direkte und gegenseitige Rekursion unterscheiden

Was ist Rekursion?

Bei Rekursion ruft eine Methode sich selbst auf, um eine kleinere Version der Aufgabe zu lösen.

Problem(n)
    löse einen kleinen Teil
    löse Problem(n - 1)
    kombiniere die Ergebnisse

Jeder Aufruf bearbeitet einen eigenen Zwischenstand. Die Aufrufe warten aufeinander und kehren später zurück.

Eine vertraute Analogie

Du öffnest eine verschachtelte Schachtel:

  1. Ist die Schachtel leer? Dann bist du fertig.
  2. Sonst öffnest du die kleinere Schachtel darin.
  3. Wenn sie leer ist, gehst du zurück und schließt die Schachteln wieder.

Das Öffnen entspricht den Methodenaufrufen; das Zurückgehen entspricht dem Rücksprung aus ihnen.

Beispielaufgabe: Zahlen aufsummieren

Aufgabe: Berechne die Summe aller ganzen Zahlen von 1 bis n, wobei n ≥ 0.

sum(4) = 4 + 3 + 2 + 1 = 10

Die Struktur wiederholt sich: Um sum(4) zu berechnen, brauche ich 4 plus sum(3).

Das kleinere Problem hat dieselbe Form: sum(3).

Schritt 1: Kleinsten Fall finden

Was ist das Ergebnis von sum(0)?

Es gibt keine Zahlen zu addieren.
sum(0) = 0

Das ist der Basisfall (base case): Er ist direkt lösbar und braucht keinen weiteren rekursiven Aufruf.

Schritt 2: Einen Fall verkleinern

Für n > 0 besteht die Summe aus:

sum(n) = n + sum(n - 1)

Das ist der rekursive Fall (recursive case). Er reduziert das Problem auf dieselbe Aufgabe mit einer kleineren Zahl.

Wichtig: n - 1 bewegt sich in Richtung des Basisfalls n == 0.

Schritt 3: Regel in Java umsetzen

int sum(int n) {
    if (n == 0) {              // Abbruchbedingung
        return 0;              // Basisfall
    }

    return n + sum(n - 1);     // rekursiver Fall
}
  • Die Abbruchbedingung erkennt, wann Schluss ist.
  • Der Basisfall liefert dann direkt ein Ergebnis.
  • Der rekursive Fall ruft die Methode mit einem kleineren Problem auf.

Schritt 4: Aufrufe verfolgen

sum(4) = 4 + sum(3)
       = 4 + 3 + sum(2)
       = 4 + 3 + 2 + sum(1)
       = 4 + 3 + 2 + 1 + sum(0)
       = 4 + 3 + 2 + 1 + 0
       = 10

Zuerst entstehen die Aufrufe bis zum Basisfall. Danach werden die wartenden Aufrufe von innen nach außen fertig berechnet.

Versuche für ein einfaches Beispiel, die Aufrufe nachzuvollziehen:

  1. Schreibe den Aufruf mit einem konkreten Wert auf, z. B. sum(4).
  2. Ersetze den Aufruf durch den rekursiven Fall: 4 + sum(3).
  3. Wiederhole das für jeden neuen Aufruf, bis der Basisfall sum(0) erreicht ist.
  4. Setze den Wert des Basisfalls ein: sum(0) = 0.
  5. Rechne zurück: Löse die wartenden Aufrufe von innen nach außen auf, bis das Endergebnis feststeht.

Der Callstack

Aufruf                        wartet auf
sum(4)                        4 + sum(3)
  sum(3)                      3 + sum(2)
    sum(2)                    2 + sum(1)
      sum(1)                  1 + sum(0)
        sum(0) liefert 0

Jeder Methodenaufruf hat eigene Parameter und lokale Variablen. Sobald ein Aufruf zurückkehrt, wird sein wartender Ausdruck vervollständigt.

Im Debugger beobachten:

  • Setze einen Breakpoint in die erste Zeile der Methode, z. B. if (n == 0), und starte im Debug-Modus.
  • Der Call Stack zeigt alle Methodenaufrufe; bei jedem Weiter (Continue) kommt ein neuer Aufruf dazu.
  • Wähle einen Eintrag im Call Stack aus: Die Debugger-View zeigt die Werte der Variablen in diesem Methodenaufrufs.

Häufiger Fehler: Kein Fortschritt

int sum(int n) {
    if (n == 0) {
        return 0;
    }
    return n + sum(n); // n wird nicht kleiner!
}

Der Basisfall wird nie erreicht. Die Methode ruft sich immer weiter auf, bis der Aufrufstapel erschöpft ist (StackOverflowError).

Prüfe bei jedem rekursiven Aufruf: Wird das Problem kleiner und kann es den Basisfall erreichen?

Dein Vorgehen für eine rekursive Lösung

  1. Beschreibe klar, welches Ergebnis die Methode liefern soll.
  2. Finde einen kleinsten Fall, den du direkt beantworten kannst.
  3. Formuliere, wie ein allgemeiner Fall eine kleinere Aufgabe derselben Art nutzt.
  4. Schreibe den Basisfall und den rekursiven Fall in Code.
  5. Prüfe an einem kleinen Beispiel die Aufrufe bis zum Basisfall und den Rückweg.
  6. Kontrolliere, dass jeder Pfad Fortschritt macht und terminiert.

Check: Passt Rekursion?

Für sum(3) gilt: sum(3) = 3 + sum(2).

  1. Was ist der Basisfall?
  2. Welchen Wert liefert sum(0)?
  3. Was gibt sum(3) zurück?
  4. Warum terminiert die Methode für n ≥ 0?

Lösung: Basisfall n == 0, Ergebnis 0; sum(3) = 3 + 2 + 1 + 0 = 6. Jeder Aufruf verringert n.

Rekursion und Iteration

Beide Techniken können wiederholte Arbeit erledigen. Sie unterscheiden sich darin, wie die Wiederholung formuliert wird.

Jede Rekursion lässt sich in eine Iteration überführen, und umgekehrt.

IterationRekursion
Wiederholung mit SchleifeWiederholung durch Methodenaufrufe
Schleifenvariable hält den FortschrittAufrufparameter halten den Fortschritt
Beendet sich, wenn die Schleifenbedingung falsch istBeendet sich, wenn ein Basisfall erreicht wird
Oft passend für einfache Zähl- und SummenaufgabenOft passend für verschachtelte oder selbstähnliche Strukturen

Welche Form übersichtlicher ist, hängt vom Problem ab.

Rekursion und Iteration auf einen Blick

Dieselbe Aufgabe: Summe von 1 bis n

int sumIterative(int n) {
    int sum = 0;
    for (int i = 1; i <= n; i++) {
        sum += i;
    }
    return sum;
}
int sumRecursive(int n) {
    if (n == 0) {
        return 0;
    }
    return n + sumRecursive(n - 1);
}

Beide Methoden liefern für n = 4 den Wert 10.

Wann passt Rekursion gut?

Frage dich, ob sich die Aufgabe natürlich so beschreiben lässt:

  • Gibt es einen kleinsten, direkt lösbaren Fall?
  • Lässt sich jeder andere Fall auf eine kleinere Aufgabe derselben Art zurückführen?
  • Wird die Aufgabe bei jedem Schritt tatsächlich kleiner und erreicht sie sicher den Basisfall?

Wenn ja, kann Rekursion die Lösung besonders klar ausdrücken. Beispiele sind Baumstrukturen, verschachtelte Ordner oder Teile-und-herrsche-Algorithmen.

Direkte und gegenseitige Rekursion

  • Direkte Rekursion: Eine Methode ruft sich selbst auf, zum Beispiel sum().
  • Gegenseitige Rekursion (mutual recursion): Mehrere Methoden rufen einander abwechselnd auf.

Auch bei gegenseitiger Rekursion braucht jeder Aufrufpfad einen Basisfall und muss sich auf ihn zubewegen.

Beispiel: Ordner rekursiv auflisten

printDirectory(folder):
    für jeden entry im folder:
        printEntry(entry)

printEntry(entry):
    wenn entry eine Datei ist:
        gib den Dateinamen aus
    sonst:
        printDirectory(entry)

Die Aufrufe wechseln zwischen den beiden Aufgaben: Ordner auflisten → Eintrag behandeln → Unterordner auflisten. Dateien enden den Weg; ein leerer Ordner hat keine Einträge.

Merksätze

  • Rekursion löst eine Aufgabe über kleinere Aufgaben derselben Art.
  • Jede rekursive Lösung braucht einen Basisfall und einen erreichbaren Abbruch.
  • Der rekursive Fall muss dem Basisfall näherkommen.
  • Iteration und Rekursion sind unterschiedliche Werkzeuge; wähle die passendere Struktur.
